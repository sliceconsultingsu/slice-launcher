# Evaluation tests (October 16, 2026)

These tests come from the [platform readiness evaluation](../../../docs/evaluations/2026-10-16-platform-readiness.md). They are **not part of CI**. The normal `pnpm test` includes only `src/**` and `apps/**`. They exercise the real sign-in verifier, membership handler, app dispatch, MCP adapter and D1 repository, using synthetic `@example.test` identities and a disposable in-memory database.

Run them from `platform/` after `pnpm install --frozen-lockfile`:

```sh
pnpm exec vitest run --config tests/evaluation/vitest.config.ts
```

| File                                                                                                  | What it checks                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `permission-matrix.test.ts`                                                                           | Every role (owner, delegated admin, activity reviewer, member, pending, suspended, invited, unknown, service, forged, unsigned) against the membership API, an app page and API, and MCP. Also delegation, revocation, last owner and identity linking                                                                                                                                                                                                                                                       |
| `concurrency`, `duplicates`, `failures`, `audit`, `migrations`, `recovery`, `malformed` (`*.test.ts`) | Concurrent and stale edits, duplicate requests, failed writes, audit consistency, migrations, restore safety and malformed stored data                                                                                                                                                                                                                                                                                                                                                                       |
| `reliability-scaling.test.ts`                                                                         | A sign-in key outage, and response size and time as membership grows                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `ui-journeys.eval.spec.ts` with `playwright.config.ts`                                                | Consultant and administrator journeys in the synthetic browser harness at desktop, phone, 200% zoom and 320 px widths, with keyboard-only checks and axe (WCAG 2.0–2.2 A/AA). Run: `pnpm exec playwright test --config tests/evaluation/playwright.config.ts`. Measurements go to `test-results/evaluation/` (or `EVAL_OUT`). On 2026-10-16, 4 of 10 journeys passed. The 6 failures come from soft quality assertions that match findings C1–C7 in the report; a failed journey step would be a regression. |
| `d1-rehearsal.sh`                                                                                     | Local-only D1 export, wipe and restore with synthetic data (`bash platform/tests/evaluation/d1-rehearsal.sh` from the repository root). It never uses `--remote`                                                                                                                                                                                                                                                                                                                                             |

Tests named `known defect (2026-10-16): …` use `it.fails`. Each one asserts the safe behavior and currently fails, so it is reported as an expected failure. When a fix lands it will start failing: change it to `it` at that point and keep it as a regression test. Promote useful cases into the main suite under `src/` once they describe intended behavior.
